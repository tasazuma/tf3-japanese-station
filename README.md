# tf3-japanese-station — 日本風モジュール駅

Transport Fever 3 用の日本風モジュール駅 mod の開発リポジトリです。
今はバニラのモデル(.mdl)だけを使っています。寸法と構成は実在の日本の駅を参考にしています。

ライセンスは [MIT](LICENSE) です。改造・再配布・別 mod での利用は自由です。
駅舎の外観や駅の構成パターンを別 mod で作る方法は「[駅舎スキン（外観）を別 mod で作る](#駅舎スキン外観を別-mod-で作る)」を見てください。

## 構成

| フォルダ | 内容 |
|---|---|
| `jpst_station/` | 旅客駅本体 mod（modId `jpst_station`） |
| `jpst_station/content/scripts/jpst/layout.lua` | 共通ルール（スロットID・寸法・レーン/線路ヘルパー）。将来は共通ライブラリ mod に切り出す予定 |
| `jpst_station/content/stations/jpst/` | 駅本体(`.con`)・スクリプト・モジュール(`.module`) |
| `jpst_building_example/` | 駅舎の外観(スキン)を別 mod で追加するサンプル（modId `jpst_building_example`、`jpst_station` に依存） |
| `tools/gen_modules.py` | 線路・ホーム・駅舎の `.module.lua` を生成する（モジュールを増減するときはこれを編集して再実行） |
| `tools/link_mods.sh` | `jpst_*` フォルダを TF3 の staging_area へシンボリックリンクする |
| `tools/test/` | ゲームを起動せずに駅スクリプトを動かすオフラインテスト |

### ファイル名の約束
- 実ファイル名には `.lua` が付きます（例: `jpst_station.con.lua`）。
- スクリプト内から参照するときは `.lua` を付けません（例: `/stations/jpst/jpst_station.script@updateFn`）。
- パスの先頭記号の意味:
  - `/path` … この mod の `content/` からのパス
  - `::/path` … ゲーム本体のパス
  - `modId::/path` … 他の mod のパス

### スロットの考え方
駅はグリッドで管理します。
- `row`: 線路と直交する方向。線路とホームが交互に並びます。
- `seg`: 線路方向。40m で 1 区切りです。
- `level`: 高さ。`0` = 地上、`1` = 高架（レール高さ約 10m）。1 つの列（row）は 1 つの高さだけを持ちます。
- `kind`: 線路・ホーム・駅舎・橋上コンコース・駅前・高架下駅舎の種別です。

スロットIDは `kind*1e7 + level*1e6 + (row+100)*1000 + (seg+100)` です。

スロット種類名は `jpst_track` / `jpst_platform`（地上）、`jpst_track_elevated` / `jpst_platform_elevated`（高架）、`jpst_building`（1 区画）〜 `jpst_building_8`（8 区画）、`jpst_concourse`（橋上コンコース。区画ごとに 1 つ）、`jpst_underviaduct`（高架下駅舎。高架の列がある区画ごとに 1 つ）、`jpst_forecourt`（駅前 1×1 マス）〜 `jpst_forecourt_4x4`、`jpst_deck`（ペデストリアンデッキ 1×1 マス）〜 `jpst_deck_4x4` です。
駅舎の `row` には「側 + 2×(区画数−1)」を入れます（側: 0 = −X 側、1 = +X 側）。`seg` は駅舎がかかる最初の区画です。
駅前の `row` には「側 + 2×d + 8×((w−1) + 4×(h−1))」を入れます（d: 駅舎から数えたマスの列 0〜3、w: 線路方向のマス数、h: 奥行き方向のマス数）。`seg` は最初の区画です。デッキは駅前と同じ `row` で `level = 1` です。
拡張 mod は、この種類名に合う `.module` を追加するだけで部品を増やせます。本体側は拡張 mod の存在を知る必要がありません。

## 開発の流れ

1. このリポジトリで編集します。
2. 初回だけリンクを作ります。
   ```sh
   tools/link_mods.sh
   ```
   staging_area は macOS の Steam から自動で探します。見つからないときや別の場所に置くときは、環境変数 `TF3_STAGING` で指定してください。
3. ゲームを起動し、mod 一覧で **JP Modular Station** を有効にして新規ゲームを始めます。
4. モジュールを追加・変更したら `python3 tools/gen_modules.py` を実行します。
5. 構文チェックには `luac -p <file>` が使えます（Homebrew の `lua` に付属）。
6. オフラインテストを実行します（Lua 5.4 以上と Python 3 が必要）。
   ```sh
   tools/test/setup.sh          # 初回だけ。自分のゲームからバニラのスクリプトを取り出す
   lua tools/test/harness.lua > /tmp/h.out
   grep -c FAIL /tmp/h.out      # 0 なら OK
   ```
   ゲーム本体のファイルはリポジトリに含めていません。`setup.sh` が `tools/test/.vanilla/`（git 管理外）へ展開します。
   ゲームのインストール先が既定と違うときは、環境変数 `TF3_GAME` で指定してください。

ログは Steam の起動オプションか、ゲーム内の開発者コンソールで確認してください。Lua のエラーはそこに出ます。

## ゲーム内での確認手順

1. 建設メニューの「鉄道駅」から **日本風モジュール駅** を選びます。
2. 番線数（1〜8）・ホーム配置（島式／対面式）・ホーム幅（5m/10m）・長さ（40〜320m）・線路種別・架線（なし／あり／あり・架線柱なし）・最初の階層（地上／高架）・ホーム屋根（なし／中央部／全体）・連絡通路（地下通路／橋上／高架下）を選んで設置します。初期値は 2 線・島式・10m・120m・標準・架線あり・屋根は中央部・地上・地下通路です。
   - 島式: 線路 2 本ごとに島式ホーム 1 面が入ります（奇数のときは最後の 1 線にもホームが付きます）。
   - 対面式: 線路 2 本の両外側にホームが付きます（2 線なら 2面2線）。3 線以上では 2 本ずつ並び、間のホームは隣と共用です。見た目は島式ホームのモデルで代用しています。
   - 各ホームの中央区画に階段（地下通路）が付きます（5 区画以上では 3 か所）。西側に小さな駅舎が付きます。
   - 連絡通路で「橋上(2F)」を選ぶと、地下通路の階段の代わりに中央区画へ橋上コンコースが付きます（地上駅のみ。高架を選んだ場合は地下通路のままです）。
   - 連絡通路で「高架下」を選ぶと、中央区画に高架下駅舎が付きます（高架駅のみ）。駅舎「なし」と組み合わせると、駅舎なしで両側の道路へ出られる高架駅になります。
3. 駅舎の裏側に道路をつなぎ、列車を走らせて旅客が乗り降りするか確認します。
4. 「モジュールの編集」で次を試します。
   - ホームの 5m/10m 切り替え
   - 階段の有無
   - 線路やホームの追加
   - 駅舎の位置変更
   - 橋上コンコースの追加・移動（地上の列だけの区画に置けます）
   - 空いている列に高架の線路・ホームを置いて、地上ホームと混在させる（地上の列の隣に高架の列を並べる）
5. 線路ツールで線路種別を変更し、架線ツールで架線を付け外しします。どちらも同じ列の連続した線路がまとめて変わります。

## 高架ホームについて（v2）
- 高架の列には高架橋（コンクリート橋の部品を流用した仮の見た目）が付き、高架下は地上コンコースになります。
- 高架ホームの階段付き区画は、高架下コンコース → 地下通路 → 駅舎とつながります。地上ホームとも地下通路でつながります。
- 駅舎は地上だけです。高架の列の外側に置いても、高架下コンコース経由でつながります。

## 高架下駅舎について（v9）
- 綱島駅・大倉山駅のように、高架橋の柱の間に改札口を設ける形を想定したモジュールです。高架の列がある区画の地上に置きます（区画ごとに 1 つ）。
- 駅舎がない外側には、道路へ出る出口（つなげられる歩行者レーン）が付きます。横に駅舎を置かなくても、高架駅を道路につなげられます。駅舎がある側は駅舎からつながります。
- 地上の列と高架の列が混ざる区画では、高架の列のかたまりごとに置かれ、駅の一番外側の列のときだけ出口が付きます。
- 置いた区画では、高架橋の仮の橋脚の代わりに、高架下駅舎の柱が並びます（外端と、6m 以上離れた列の境目に、線路方向 10m おき）。
- 同梱の見た目は「柱」です: 1m 角のコンクリート柱・出口脇の券売機・ベンチ・くずかご。壁で囲った駅舎や店舗は、今後スキンで追加する予定です。

### 高架下駅舎のスキンを別 mod で作る
`type = "jpst_underviaduct"` のモジュールで、`updateScript` / `getModelsScript` に `jpst_station::/stations/jpst/jpst_modules.script@underviaduct.updateFn` / `@underviaduct.getModelsFn` を指定し、`params` に次を書きます。モデルの書き方（`id`, `x`, `y`, `z`, `rotZ` または `transf`）は駅舎スキンと同じです。

| キー | 意味 | 省略時 |
|---|---|---|
| `columns` | 柱。`{ id, rotZ, scale = {sx, sy, sz}, offset = {x, y}, ys = {…}, minGap }`。高架のかたまりの両外端と、`minGap` m 以上離れた列の境目に、区画中心から `ys` の位置へ置きます | 柱なし |
| `exitModels` | 出口ごとに置くモデル。原点は列の外端（区画の中心）、`+X` が線路方向、`−Y` が駅の外側です。出口の通路は `x = 0` を通り、舗装は `x = −8〜8`、`y = 0〜−4` です | なし |
| `hallModels` | 高架のかたまりごとに置くモデル。原点はかたまりの中心（`x` が線路と直交、`y` が線路方向） | なし |

歩行者レーンは区画中心（`y = 0`）を横切る通路と、各列の中心線（`x` 方向の位置ごとに `y = −20〜20`）にあります。モデルはこれを避けて置いてください。

## 橋上コンコース・自由通路について（v3）
- 川崎駅のような橋上駅を想定したモジュールです。レール面から約 9m の高さに、駅の全幅にわたる 2 階の通路を架けます。
- 各ホームの両端（区画の境目）から階段で上がれます。
- 駅舎がある側は駅舎へ降ります。駅舎がない側は外側に降りる階段（出口）が付き、その先に道路をつなげます。
- 両側の出口・駅舎は通路でつながっているので、駅の反対側へ抜ける自由通路にもなります。
- 見た目は仮です。床・階段・柱はコンクリート橋の部品を引き伸ばして代用しています。
- 高架の列がある区画には置けません（置いても無視されます）。

## 大きな駅舎（東京駅タイプ, v4）
- 駅舎は 1〜8 区画（40〜320m）の長さで置けます。置き場所に入る長さのスロットだけが出ます（他の駅舎と重なる位置には出ません）。
- 駅の設置時に「駅舎: 小さな駅舎 / 大きな駅舎（全長）/ なし」を選べます。大きな駅舎は −X 側に駅の全長で置かれます。
- 駅舎は、かかっている区画ごとに 地下通路・高架下コンコース・外側の地上ホーム・橋上コンコース へつながります。区画ごとに列の外端がずれていても、駅舎の正面は一番外側にそろい、すき間は通路でつなぎます。
- 駅舎がかかる区画の列がなくなると、その駅舎は無視されます（スロットは残るので撤去できます）。
- 同梱の外観はサンプルです: 小さな駅舎（C 時代）と、レンガ駅舎（A 時代の赤レンガ駅舎を並べたもの、各長さ）。

## 駅舎スキン（外観）を別 mod で作る
駅舎の機能（歩行者レーン・道路接続・地形）は本体が受け持ち、外観は `.module` ファイルだけで決まります。
誰でも別 mod で外観を追加できます。完全な例は `jpst_building_example/` を見てください。

1. `mod.json` の `dependencies` に `jpst_station` を書きます（`"loadBefore": true`）。
2. `content/` の下に `.module.lua` を 1 つ作ります。必要なのは次の項目です。
   - `type`: `"jpst_building"`（40m）または `"jpst_building_2"` 〜 `"jpst_building_8"`（80〜320m）
   - `updateScript.fileName`: `"jpst_station::/stations/jpst/jpst_modules.script@building.updateFn"`
   - `getModelsScript.fileName`: `"jpst_station::/stations/jpst/jpst_modules.script@building.getModelsFn"`
   - 両方の `params` に同じ設定表を渡します:

| キー | 意味 | 省略時 |
|---|---|---|
| `models` | 置くモデルの一覧。`"x.mdl"`、`{ id = "x.mdl", x =, y =, z =, rotZ = 度 }`、`{ id = "x.mdl", transf = {16 個の数} }` のどれか | なし |
| `length` | 線路方向の長さ(m)。地形をならす範囲 | 40×区画数−2 |
| `depth` | 線路から離れる方向の奥行き(m)。道路接続レーンは `y = −(depth−3)`。`metadata.jpst_depth` にも同じ値を書いてください | 17 |
| `height` | 当たり判定の高さ(m) | 8 |

3. 座標系: 原点は駅舎正面の中央です。正面（`y = 0`）が線路側、`+X` が線路方向、建物は `−Y` 側に伸びます。1 区画は 40m です。
4. `metadata.snapPoint` を `transf.transl(vec3.new(0, −(depth+7), 0))` にすると、道路が駅舎の裏に吸着します。
5. `metadata.jpst_depth` に `depth` と同じ値を書きます。駅前広場はこの値を見て駅舎の裏から始まります（書かないと 17m とみなします）。
6. 料金・収容人数・利用圏（`moreCapacity` など）は普通のモジュールと同じように `metadata` に書きます。

## 駅前（v5）
- 駅舎の裏側に、40m 四方のマスで区切った「駅前」スロットが出ます。駅舎がある区画の外側だけで、奥行きは 4 マス（160m）までです。
- 駅前の始まりは、その側で一番奥行きのある駅舎の裏です。浅い駅舎との間のすき間は広場が埋めて、駅舎の道路側レーンまで歩行者通路をつなぎます。
- 広場には歩行者レーンが格子状に通っていて、隣の広場とつながります。レーンは道路と接続できます（広場の脇に道路を通すと広場から出入りできます）。
- 同梱の外観はサンプルです: 舗装広場（街灯・ベンチ）と緑地広場（芝生・木）、それぞれ 1×1 / 2×1 / 2×2 マス。メニューでは「装飾」に入っています。
- 駅舎がなくなった区画の広場、他の広場と重なる広場は無視されます（スロットは残るので撤去できます）。
- 駅舎から離れたマスにだけ広場を置くと、駅舎とはつながりません（道路につなげば普通の広場として使えます）。

### 駅前のモジュールを別 mod で作る
駅舎スキンと同じく `.module.lua` だけで作れます。
- `type`: `"jpst_forecourt"`（1×1 マス）または `"jpst_forecourt_<w>x<h>"`（w: 線路方向、h: 奥行き方向。各 1〜4）
- `updateScript.fileName`: `"jpst_station::/stations/jpst/jpst_modules.script@forecourt.updateFn"`
- `getModelsScript.fileName`: `"jpst_station::/stations/jpst/jpst_modules.script@forecourt.getModelsFn"`
- 座標系: 原点は広場の中心。`+X` が線路方向、`+Y` が駅舎側です。広場は `x = ±w×20`, `y = ±h×20` に広がります。

| キー | 意味 | 省略時 |
|---|---|---|
| `ground` | 地面の塗り（`groundFaces` の `modes`） | 舗装＋縁石 |
| `terrain` | 地形の合わせ方（`"EQUAL"` など） | `"EQUAL"` |
| `cellModels` | 40m のマスごとに置くモデル。座標はマスの中心から（書き方は駅舎の `models` と同じ） | なし |
| `models` | 広場全体に 1 回だけ置くモデル。座標は広場の中心から | なし |
| `lanes` | 歩行者レーンの形。`"cross"`（十字）、`"along"`（一の字・線路方向）、`"through"`（一の字・駅舎方向）、`"none"` | `"cross"` |

歩行者レーンはマスの中心を通り（`lanes` で十字・一の字を選べます）、マスの端にノードがあります。駅舎につながるのは駅舎方向のレーン（`"cross"` / `"through"`）だけです。商店街のように建物を並べるときは、一の字にしてレーンの両脇に置けます。モデルはレーン（`x = 0` または `y = 0` の線）を避けて置くと見た目がきれいです。

## ペデストリアンデッキ（v6）
- 駅前と同じ 40m マスの上、高さ 9m（橋上コンコースの床と同じ）に置くデッキです。地上の広場とは別スロットなので、広場の上にデッキを重ねられます。
- 高さの考え方: 実際のデッキは道路から 6〜8m 程度（バスの高さ＋桁）ですが、このmodでは「2F」の高さを 9m に統一して、橋上コンコースとそのまま平らにつながるようにしています。
- 駅舎の裏の列（d = 0）のデッキは、駅舎の中を 2F の高さで通り抜けます。その区画に橋上コンコースがあればそのまま 2F で直結し、なければ駅舎のホールへ降ります（高架駅でも使えます）。
- 階段（既定は一番外側の列の各マスに 1 つ）で地上へ降ります。階段の下はマスの中心で地上の広場のレーンとつながり、広場がなくても道路と接続できます。
- 同梱の外観はサンプルです: コンクリートのデッキ（幅 8m の通路を格子状に組んだもの・街灯・ベンチ）1×1 / 2×1 / 2×2。メニューでは「装飾」に入っています。

### デッキのモジュールを別 mod で作る
- `type`: `"jpst_deck"` または `"jpst_deck_<w>x<h>"`
- `updateScript.fileName`: `"jpst_station::/stations/jpst/jpst_modules.script@deck.updateFn"`（`getModelsScript` は `@deck.getModelsFn`）
- 座標系は駅前と同じです。`models` / `cellModels` の `z = 0` はデッキの床面です。

| キー | 意味 | 省略時 |
|---|---|---|
| `lanes` | 通路の形。`"cross"` / `"along"` / `"through"`（駅前と同じ） | `"cross"` |
| `stairs` | 地上への階段。`"outer"`（外側の列だけ）、`"all"`（全マス）、`"none"` | `"outer"` |
| `walkWidth` | 通路の幅（m, 3〜10） | `8` |
| `structure` | 仮の構造物（コンクリートの通路・橋脚・階段）を置くか。`false` にするとスキン側で全部描きます | `true` |
| `cellModels` / `models` | 駅前と同じ（床面基準） | なし |

階段はマスの中心から `x = +16` の位置にあり、通路の端から 15m かけて駅と反対側へ降ります。モデルはここと通路（`x = 0` / `y = 0` の線、幅 `walkWidth`）を避けて置いてください。

## バスロータリー（v7）
- 駅前と同じ地上の 40m マスに置く、バス乗り場付きのロータリーです（広場と同じスロットなので、広場と並べたり、デッキの下に置いたりできます）。
- 外側の辺（駅と反対側）の中央に短い道路の端（スタブ）があり、ここに街の道路をつなぎます。バスは右側通行で入り（中心から `+2.5m`）、反時計回りに島を回って駅舎側の乗り場に停まり、`-2.5m` 側から出ていきます。
- 乗り場はマスの列ごとに 1 つ（1×1 なら 1 つ、2×1 なら 2 つ）。乗り場の歩道は駅舎・隣の広場の歩行者レーンとつながります。
- 同梱の外観はサンプルです: 上屋・バス停標識・街灯・島の木（1×1 / 2×1）。メニューでは「装飾」に入っています。
- 駅舎のない側に置いたロータリーは無視されます。

### ロータリーのモジュールを別 mod で作る
- `type`: 駅前と同じ（`"jpst_forecourt"` / `"jpst_forecourt_<w>x<h>"`）
- `updateScript.fileName`: `"jpst_station::/stations/jpst/jpst_modules.script@busrotary.updateFn"`（`getModelsScript` は `@busrotary.getModelsFn`）
- 座標系は駅前と同じです。形は `layout.ROTARY`（歩道 8m、停車線 10m、入口 8m、折り返し 12m）で決まります。

| キー | 意味 | 省略時 |
|---|---|---|
| `ground` / `sidewalkGround` / `islandGround` | 車道・歩道・島の地面 | アスファルト / 歩道 / 芝生 |
| `terrain` | 地形の合わせ方 | `"EQUAL"` |
| `streetTemplate` | スタブの道路の種類 | 駅の入口用道路 |
| `stopModels` | 乗り場ごとに置くモデル。座標は乗り場の縁石の中心から | なし |
| `models` | ロータリー全体に 1 回だけ置くモデル。座標は中心から | なし |

## 駅名標・番線表示（v8）
- ホームの各区画（40m）に、照明柱 3 本・駅名標 2 枚（柱から吊り下げ）・番線表示 1 枚（中央の柱）を置きます。モデルはゲーム本体のもの（era_c）です。
- 番線は線路の列ごとに 1 から数えます。駅舎が +X 側にだけあるときは +X 側から、それ以外は −X 側から数えます（駅舎側が 1 番線）。
- 番線表示はホームの両側の線路番号を出します。線路のない側（相対式ホームの外側など）や、高さの違う線路の側は空欄です。
- 駅名標の文字はゲームが駅名を自動で入れます。

### 駅名標・番線表示を別 mod で差し替える
ホームのモジュール（`jpst_platform_*`）の `params` に `signs` を書くと、置くモデルを変えられます。座標はホーム区画の中心が原点で、`x` がホームの幅方向、`y` が線路方向（−20〜20）、`z` は線路面からの高さ（ホーム面は 1.1）です。モデルは本体のホーム部品と同じく、`y` 方向に向けて置かれます。

| キー | 意味 | 省略時 |
|---|---|---|
| `id` | モデル | 必須 |
| `x` / `y` / `z` | 位置 | 0 |
| `rotZ` | 追加の回転（度） | 0 |
| `label` | `"number"`: ラベル 1・2 に −X 側、3・4 に +X 側の番線を入れる。`"name"`: 駅名（`STATION_NAME` ラベル） | なし |

## 架線柱なしの線路（v10）
- 日本の駅ではホームと線路の間に架線柱を立てないことが多いため、架線（電線）だけを張り、架線柱を描かない線路を用意しました。電化されているので電車も走れます。
- 設置時に「架線」で「あり（架線柱なし）」を選ぶか、モジュールの編集で「線路（標準・電化・架線柱なし）」などを選びます。列ごと・区画ごとに選べるので、屋根のある区画だけ架線柱をなくす、といった使い方ができます。
- 中身は、ゲーム本体の電化線路をコピーし、架線柱のモデルだけ透明なモデルに差し替えた、駅専用の線路種別です（`jpst_station/content/infrastructure/jpst_track/`、`tools/gen_modules.py` がゲーム本体のファイルから生成します）。線路ツールのメニューには出ません。
- 架線ツールで架線を外すと、普通の非電化線路になります。もう一度付けると、架線柱のある線路に戻ります。

## ホーム屋根（上家, v11）
- ホームの各区画（40m）の上に屋根スロットがあり、「ホーム屋根（木造／鉄骨／モダン）」を置けます。モデルはゲーム本体のモジュール駅の屋根（era_a/b/c の `perron_5_roof`）です。
- 屋根はホーム幅 5m ごとに 1 本並びます（10m のホームなら 2 本）。前後の区画に屋根がない側には、自動で端の部品が付きます。
- 設置時の「ホーム屋根」で、なし／中央部（ゲーム標準と同じく 200m まではホーム全体、それより長いと両端 40m ずつを除いた部分）／全体を選べます。初期値は中央部です（本体ではモダン屋根）。
- 地上・高架どちらのホームにも置けます。屋根のある区画は、架線柱なしの線路（v10）と組み合わせると日本の駅らしくなります。

### 屋根のスキンを別 mod で作る
`type = "jpst_roof"` のモジュールを作り、`updateScript` に `jpst_station::/stations/jpst/jpst_modules.script@roof.updateFn`（`getModelsScript` は `@roof.getModelsFn`）を指定します。`params` に次を書きます。モデルは本体の屋根と同じく、長さ 40m を `x` 0〜40 方向に、ホーム面（高さ 1.1）を基準に作られたものを想定しています。

| キー | 意味 | 省略時 |
|---|---|---|
| `roofModel` | 幅 5m 分の屋根（ホーム幅 5m ごとに置く） | なし |
| `endModel` | 屋根の端の部品（屋根が途切れる側に置く） | なし |

## 既知の制限
- 1 つの列の中で地上と高架は混ぜられません（スロットも同じ高さしか出ません）。坂（地上→高架の勾配）はありません。駅の外で線路を上げ下げしてください。
- 列と列の間に空き列があると、地下通路が途切れます。
- 3 層構造・エスカレーターは今後対応します。地下コンコース・地下街は、駅ビルと駅前広場で表現できるため見送りました。
- 同じ列に幅の違うホームを混ぜると、すき間ができます。
- ホームは、階段付き区画か橋上コンコースを経由しないと駅舎・道路につながりません。
- 駅舎も、橋上コンコースや高架下駅舎の出口もないと、道路に接続できません。
- 番線表示の数字は、路線設定画面のホーム番号（ゲームの乗り場番号）とは一致しません。
- バスロータリーは右側通行を前提にしています（ゲーム本体に左側通行の設定はありません。道路 mod で左側通行にした場合には対応していません）。
- まだゲーム内で検証していない点:
  - 高架線路（BRIDGE 指定のエッジ）が駅の中で正しく描画されるか、橋脚が自動で付くか
  - 高架橋・橋脚の仮モデルの見た目と位置
  - 高架スロットのクリックしやすさ、急な階段レーン
  - モデルの位置合わせ
  - 階段・駅舎まわりの歩行者レーン
  - 停車位置
  - 橋上コンコースの見た目（床・階段・柱の位置）と、自由通路を一般の歩行者が通り抜けるか
  - ホーム屋根の位置合わせ（階段・駅名標・照明柱との重なり、高架での高さ）と、屋根スロットのクリックしやすさ
  - 高架下駅舎の柱・券売機の向きと位置（ゲームが自動で付ける太い橋脚と重なることがあります）
  - レンガ駅舎のつなぎ目の見た目（別 mod からのスクリプト参照と地上駅での駅舎追加はゲーム内で確認済み）
