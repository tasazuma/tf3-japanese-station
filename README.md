# tf3-japanese-station — 日本風モジュール駅

Transport Fever 3 用の日本風モジュール駅 mod の開発リポジトリです。
今はバニラのモデル(.mdl)だけを使っています。寸法と構成は実在の日本の駅を参考にしています。

ライセンスは [MIT](LICENSE) です。改造・再配布・別 mod での利用は自由です。
駅舎の外観や駅の構成パターンを別 mod で作る方法は「[駅舎スキン（外観）を別 mod で作る](#駅舎スキン外観を別-mod-で作る)」を見てください。

## 構成

| フォルダ | 内容 |
|---|---|
| `jpst_station/` | 旅客駅本体 mod（modId `jpst_station`） |
| `jpst_station/content/scripts/jpst/layout.lua` | 共通ルール（スロットID・寸法・レーン/線路ヘルパー）。将来は共通ライブラリ mod に切り出す予定 |
| `jpst_station/content/stations/jpst/` | 駅本体(`.con`)・スクリプト・モジュール(`.module`) |
| `jpst_building_example/` | 駅舎の外観(スキン)を別 mod で追加するサンプル（modId `jpst_building_example`、`jpst_station` に依存） |
| `tools/gen_modules.py` | 線路・ホーム・駅舎の `.module.lua` を生成する（モジュールを増減するときはこれを編集して再実行） |
| `tools/link_mods.sh` | `jpst_*` フォルダを TF3 の staging_area へシンボリックリンクする |
| `tools/test/` | ゲームを起動せずに駅スクリプトを動かすオフラインテスト |

### ファイル名の約束
- 実ファイル名には `.lua` が付きます（例: `jpst_station.con.lua`）。
- スクリプト内から参照するときは `.lua` を付けません（例: `/stations/jpst/jpst_station.script@updateFn`）。
- パスの先頭記号の意味:
  - `/path` … この mod の `content/` からのパス
  - `::/path` … ゲーム本体のパス
  - `modId::/path` … 他の mod のパス

### スロットの考え方
駅はグリッドで管理します。
- `row`: 線路と直交する方向。線路とホームが交互に並びます。
- `seg`: 線路方向。40m で 1 区切りです。
- `level`: 高さ。`0` = 地上、`1` = 高架（レール高さ約 10m）。1 つの列（row）は 1 つの高さだけを持ちます。
- `kind`: 線路・ホーム・駅舎・橋上コンコースの種別です。

スロットIDは `kind*1e7 + level*1e6 + (row+100)*1000 + (seg+100)` です。

スロット種類名は `jpst_track` / `jpst_platform`（地上）、`jpst_track_elevated` / `jpst_platform_elevated`（高架）、`jpst_building`（1 区画）〜 `jpst_building_8`（8 区画）、`jpst_concourse`（橋上コンコース。区画ごとに 1 つ）です。
駅舎の `row` には「側 + 2×(区画数−1)」を入れます（側: 0 = −X 側、1 = +X 側）。`seg` は駅舎がかかる最初の区画です。
拡張 mod は、この種類名に合う `.module` を追加するだけで部品を増やせます。本体側は拡張 mod の存在を知る必要がありません。

## 開発の流れ

1. このリポジトリで編集します。
2. 初回だけリンクを作ります。
   ```sh
   tools/link_mods.sh
   ```
   staging_area は macOS の Steam から自動で探します。見つからないときや別の場所に置くときは、環境変数 `TF3_STAGING` で指定してください。
3. ゲームを起動し、mod 一覧で **JP Modular Station** を有効にして新規ゲームを始めます。
4. モジュールを追加・変更したら `python3 tools/gen_modules.py` を実行します。
5. 構文チェックには `luac -p <file>` が使えます（Homebrew の `lua` に付属）。
6. オフラインテストを実行します（Lua 5.4 以上と Python 3 が必要）。
   ```sh
   tools/test/setup.sh          # 初回だけ。自分のゲームからバニラのスクリプトを取り出す
   lua tools/test/harness.lua > /tmp/h.out
   grep -c FAIL /tmp/h.out      # 0 なら OK
   ```
   ゲーム本体のファイルはリポジトリに含めていません。`setup.sh` が `tools/test/.vanilla/`（git 管理外）へ展開します。
   ゲームのインストール先が既定と違うときは、環境変数 `TF3_GAME` で指定してください。

ログは Steam の起動オプションか、ゲーム内の開発者コンソールで確認してください。Lua のエラーはそこに出ます。

## ゲーム内での確認手順

1. 建設メニューの「鉄道駅」から **日本風モジュール駅** を選びます。
2. 番線数（1〜8）・ホーム配置（島式／対面式）・ホーム幅（5m/10m）・長さ（40〜320m）・線路種別・架線・最初の階層（地上／高架）・連絡通路（地下通路／橋上）を選んで設置します。初期値は 2 線・島式・10m・120m・標準・架線あり・地上・地下通路です。
   - 島式: 線路 2 本ごとに島式ホーム 1 面が入ります（奇数のときは最後の 1 線にもホームが付きます）。
   - 対面式: 線路 2 本の両外側にホームが付きます（2 線なら 2面2線）。3 線以上では 2 本ずつ並び、間のホームは隣と共用です。見た目は島式ホームのモデルで代用しています。
   - 各ホームの中央区画に階段（地下通路）が付きます（5 区画以上では 3 か所）。西側に小さな駅舎が付きます。
   - 連絡通路で「橋上(2F)」を選ぶと、地下通路の階段の代わりに中央区画へ橋上コンコースが付きます（地上駅のみ。高架を選んだ場合は地下通路のままです）。
3. 駅舎の裏側に道路をつなぎ、列車を走らせて旅客が乗り降りするか確認します。
4. 「モジュールの編集」で次を試します。
   - ホームの 5m/10m 切り替え
   - 階段の有無
   - 線路やホームの追加
   - 駅舎の位置変更
   - 橋上コンコースの追加・移動（地上の列だけの区画に置けます）
   - 空いている列に高架の線路・ホームを置いて、地上ホームと混在させる（地上の列の隣に高架の列を並べる）
5. 線路ツールで線路種別を変更し、架線ツールで架線を付け外しします。どちらも同じ列の連続した線路がまとめて変わります。

## 高架ホームについて（v2）
- 高架の列には高架橋（コンクリート橋の部品を流用した仮の見た目）が付き、高架下は地上コンコースになります。
- 高架ホームの階段付き区画は、高架下コンコース → 地下通路 → 駅舎とつながります。地上ホームとも地下通路でつながります。
- 駅舎は地上だけです。高架の列の外側に置いても、高架下コンコース経由でつながります。

## 橋上コンコース・自由通路について（v3）
- 川崎駅のような橋上駅を想定したモジュールです。レール面から約 9m の高さに、駅の全幅にわたる 2 階の通路を架けます。
- 各ホームの両端（区画の境目）から階段で上がれます。
- 駅舎がある側は駅舎へ降ります。駅舎がない側は外側に降りる階段（出口）が付き、その先に道路をつなげます。
- 両側の出口・駅舎は通路でつながっているので、駅の反対側へ抜ける自由通路にもなります。
- 見た目は仮です。床・階段・柱はコンクリート橋の部品を引き伸ばして代用しています。
- 高架の列がある区画には置けません（置いても無視されます）。

## 大きな駅舎（東京駅タイプ, v4）
- 駅舎は 1〜8 区画（40〜320m）の長さで置けます。置き場所に入る長さのスロットだけが出ます（他の駅舎と重なる位置には出ません）。
- 駅の設置時に「駅舎: 小さな駅舎 / 大きな駅舎（全長）/ なし」を選べます。大きな駅舎は −X 側に駅の全長で置かれます。
- 駅舎は、かかっている区画ごとに 地下通路・高架下コンコース・外側の地上ホーム・橋上コンコース へつながります。区画ごとに列の外端がずれていても、駅舎の正面は一番外側にそろい、すき間は通路でつなぎます。
- 駅舎がかかる区画の列がなくなると、その駅舎は無視されます（スロットは残るので撤去できます）。
- 同梱の外観はサンプルです: 小さな駅舎（C 時代）と、レンガ駅舎（A 時代の赤レンガ駅舎を並べたもの、各長さ）。

## 駅舎スキン（外観）を別 mod で作る
駅舎の機能（歩行者レーン・道路接続・地形）は本体が受け持ち、外観は `.module` ファイルだけで決まります。
誰でも別 mod で外観を追加できます。完全な例は `jpst_building_example/` を見てください。

1. `mod.json` の `dependencies` に `jpst_station` を書きます（`"loadBefore": true`）。
2. `content/` の下に `.module.lua` を 1 つ作ります。必要なのは次の項目です。
   - `type`: `"jpst_building"`（40m）または `"jpst_building_2"` 〜 `"jpst_building_8"`（80〜320m）
   - `updateScript.fileName`: `"jpst_station::/stations/jpst/jpst_modules.script@building.updateFn"`
   - `getModelsScript.fileName`: `"jpst_station::/stations/jpst/jpst_modules.script@building.getModelsFn"`
   - 両方の `params` に同じ設定表を渡します:

| キー | 意味 | 省略時 |
|---|---|---|
| `models` | 置くモデルの一覧。`"x.mdl"`、`{ id = "x.mdl", x =, y =, z =, rotZ = 度 }`、`{ id = "x.mdl", transf = {16 個の数} }` のどれか | なし |
| `length` | 線路方向の長さ(m)。地形をならす範囲 | 40×区画数−2 |
| `depth` | 線路から離れる方向の奥行き(m)。道路接続レーンは `y = −(depth−3)` | 17 |
| `height` | 当たり判定の高さ(m) | 8 |

3. 座標系: 原点は駅舎正面の中央です。正面（`y = 0`）が線路側、`+X` が線路方向、建物は `−Y` 側に伸びます。1 区画は 40m です。
4. `metadata.snapPoint` を `transf.transl(vec3.new(0, −(depth+7), 0))` にすると、道路が駅舎の裏に吸着します。
5. 料金・収容人数・利用圏（`moreCapacity` など）は普通のモジュールと同じように `metadata` に書きます。

## 既知の制限
- 1 つの列の中で地上と高架は混ぜられません（スロットも同じ高さしか出ません）。坂（地上→高架の勾配）はありません。駅の外で線路を上げ下げしてください。
- 列と列の間に空き列があると、地下通路が途切れます。
- 地下コンコース・駅前広場・ペデストリアンデッキ・3 層構造は今後対応します。
- 同じ列に幅の違うホームを混ぜると、すき間ができます。
- ホームは、階段付き区画か橋上コンコースを経由しないと駅舎・道路につながりません。
- 駅舎も橋上コンコースの出口もないと、道路に接続できません。
- 番線表示や駅名標はまだありません。
- まだゲーム内で検証していない点:
  - 高架線路（BRIDGE 指定のエッジ）が駅の中で正しく描画されるか、橋脚が自動で付くか
  - 高架橋・橋脚の仮モデルの見た目と位置
  - 高架スロットのクリックしやすさ、急な階段レーン
  - モデルの位置合わせ
  - 階段・駅舎まわりの歩行者レーン
  - 停車位置
  - 橋上コンコースの見た目（床・階段・柱の位置）と、自由通路を一般の歩行者が通り抜けるか
  - レンガ駅舎のつなぎ目の見た目（別 mod からのスクリプト参照と地上駅での駅舎追加はゲーム内で確認済み）
